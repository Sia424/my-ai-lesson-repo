# 01．认识 AI Agent

AI 可以解释问题、整理资料、起草内容，也可以借助工具完成文件处理等任务。这一章先解释这些能力背后的常见概念，再列出开始学习需要的准备。

读完后，你应该能判断：一项任务需要给 AI 什么材料、它需要什么工具，以及结果该怎么检查。第一次阅读先理解大模型、提示词和 Agent，其余术语遇到时再回来查。

## 1．从一个任务认识 AI Agent

假设你想写一篇公众号文章，主题是“下班后怎样留出一点阅读时间”。以下为虚构的写作需求：

> 写给想读书、但下班后经常刷手机的上班族。重点介绍三个做法：从每天读 10 分钟开始，把书放在容易拿到的位置，读完记下一句话。希望读者看完后能选一个做法尝试。

同样是“帮我写公众号文章”，你可能需要三种不同的帮助：

| 你的需求 | AI 需要做什么 | 你检查什么 |
|---|---|---|
| 想知道怎样写 | 建议文章角度和提纲 | 是否符合主题和目标读者 |
| 想得到文章初稿 | 根据需求和素材组织文章 | 是否覆盖要点、有没有编造经历或数据 |
| 想得到保存好的稿件 | 生成初稿，调用文件工具，保存并检查文件 | 文件是否存在、能否打开、内容是否完整 |

第三种任务需要 AI 把回答转化为操作。**Agent（智能体）可以理解为能使用工具、根据执行结果继续推进任务的 AI 助理。**它通常会拆分任务、调用工具、查看结果，再决定下一步。[Anthropic 对 Agent 的说明](https://www.anthropic.com/research/building-effective-agents)

比如，它先读取写作需求和素材，再起草文章，最后保存成文件。假如保存失败，它可能检查原因并重试；假如你要求加入自己的亲身经历，却没有提供素材，它应该向你询问，而不是替你编造。

Agent 能做哪些事，取决于模型能力、接入的工具和获得的权限。会聊天的应用也可能带有搜索、文件处理等功能，因此不能仅凭“有没有对话框”判断它是不是 Agent。

你负责说明目标、提供材料、确定允许操作的范围，并检查成果。AI 可以帮助推进工作，但不能替你确认材料中没有的事实。

## 2．理解 AI 的基础概念

### 大语言模型（LLM）：处理语言的基础能力

LLM 是 Large Language Model 的缩写。它通过大量数据训练，学习语言和内容之间的规律，并根据当前输入生成回答。拟文章提纲、整理素材、修改段落，都是常见用途。

可以把模型理解为 AI 应用的“语言处理引擎”。你打开的应用还会提供对话界面、文件上传、联网搜索等功能。**模型与应用不是同一层东西**：同一个模型可以接入不同应用，一个应用也可能提供多个模型。

模型生成回答时，并不意味着它刚刚搜索了互联网。遇到新闻、价格或产品功能等问题，要确认应用是否实际查询了资料，并检查来源。

也不需要先选出一个“最强模型”。先用同一份材料和同一项要求比较：信息是否准确、要求是否遵守、结果是否容易检查，以及使用成本是否合适。

### Token：模型处理内容时使用的计量单位

文字进入模型前，会被拆成称为 Token 的小片段。一个 Token 可能是一个字、词的一部分或标点；具体拆法取决于模型使用的分词方式。图片、音频等输入也有各自的处理和计量方式。

**Token 与汉字没有通用的固定换算比例。**不能直接把“1,000 个 Token”当成固定数量的汉字；需要准确数值时，应使用对应模型提供的计数工具。[Google 的 Token 说明](https://ai.google.dev/gemini-api/docs/tokens)

对初学者来说，知道它影响两件事即可：

- **用量和费用**：通过 API 调用模型时，服务商常按输入、输出等用量计费。API 可以理解为软件调用另一项服务的接口。直接使用 AI 应用，也可能按订阅、次数或积分收费。
- **一次能处理多少内容**：输入材料、对话记录和回答都可能占用模型的处理额度，具体规则看对应服务说明。

学习初期不用手算 Token，也不用先购买 API。

### 上下文窗口：一次工作能放下多少材料

“上下文”是模型当前回答时可使用的信息，例如你的任务说明、对话记录、文件内容和工具返回的结果。“上下文窗口”就是容纳这些信息的容量，通常用 Token 表示。

把它想成工作台：台面再大，也有放不下的时候。对话很长时，应用可能压缩历史、取出部分内容或提示超限，具体行为因产品而异。窗口大小也不等于长期记忆能力。[Google 的上下文窗口说明](https://ai.google.dev/gemini-api/docs/tokens)

工作台够大，不代表每个细节都一定被用对。写文章时，主题、读者、素材和修改意见都可能成为上下文。重要要求应集中写清；发现 AI 忘了“写给上班族”时，先检查当前任务是否包含这项要求，再补充说明。

### 多模态：处理文字之外的信息

“模态”可以理解为信息形式，例如文字、图片、音频和视频。多模态模型能够处理多种信息形式。

例如，写公众号文章时，可以让支持图片输入的应用分析排版参考截图，让支持音频输入的应用把口述想法整理成写作素材。能读图片，不代表一定能生成封面图；支持某种模型，也不代表应用开放了它的全部能力。使用前看当前界面的上传入口和功能说明。

### 训练与推理：学习规律与使用能力

**训练**是利用数据调整模型，让它学会规律的过程；**推理**是训练后的模型根据输入产生输出的过程。这里的“推理”也包括生成一句普通回答，并不专指复杂的逻辑推导。

你在对话框中补充一篇自己写过的文章，让 AI 参考表达方式，通常是在提供本次任务的上下文，不等于现场重新训练了模型。普通使用者先学会提供有效材料、描述任务和检查结果即可。

## 3．让 AI 按要求工作

### Prompt（提示词）：给 AI 的任务说明

提示词就是你交给 AI 的要求。它可以是一句话，也可以包含背景、材料、限制和输出格式。

“帮我写一篇公众号文章”范围太大。换成下面这段，任务会更明确：

```text
请帮我写一篇公众号文章初稿。

主题：下班后怎样留出一点阅读时间。
读者：想读书、但下班后经常刷手机的上班族。
目的：让读者看完后，能选一个做法尝试。

要点：
1. 从每天读 10 分钟开始，不急着读完一本书。
2. 把书放在容易拿到的位置，减少开始阅读的准备。
3. 读完记下一句话，不要求写完整读书笔记。

输出要求：
1. 提供一个标题和约 600 字的正文，用三个小标题展开上述要点。
2. 用日常语言解释，每个做法配一个具体的行动建议。
3. 不编造我的亲身经历、研究数据或名人名言。
4. 如需举例，明确写成假设场景；结尾邀请读者选一个做法尝试。
```

“主题”可以换成你想写的内容；“读者”和“目的”决定文章需要解释什么；“要点”给出希望表达的内容；“输出要求”限定篇幅、结构和表达边界。这里的“每天读 10 分钟”是练习中的行动建议，不是经过研究证明的效果承诺。

提示词的重点是减少歧义。写得长不一定更好，写得清楚也不能保证回答完全正确。

### 幻觉：看起来合理，却没有事实依据

如果 AI 在上例中写出“研究证明，每天阅读 10 分钟能提升 50% 的工作效率”，却没有真实依据，或者写成“我坚持一年，读完了 100 本书”，而你没有提供这样的经历，这就是需要警惕的编造。

流畅的文字和肯定的语气都不能证明内容真实。检查结果时，要把具体数字、人名、日期和引用逐项与原始材料对照；材料没有写的内容，应标注缺失或另行核实。

### RAG（检索增强生成）：先找资料，再组织回答

RAG 是 Retrieval-Augmented Generation 的缩写。基本过程是：先从资料中检索相关内容，再把检索结果交给模型，帮助它回答问题。[Google Cloud 的 RAG 说明](https://cloud.google.com/use-cases/retrieval-augmented-generation)

例如，你积累了一个包含过往文章和阅读笔记的素材库。写新文章时，向支持检索的系统提问“我以前写过哪些培养阅读习惯的方法”，系统先找出相关片段，再交给模型整理为可用素材。你可以把它理解为“先翻资料，再动笔”。

**RAG 能帮助回答获得依据，但不能保证答案正确。**资料可能过期，检索可能漏掉关键段落，模型也可能误解原文。即使回答带有引用，也要确认引用内容确实支持结论。[Google Research 对 RAG 错误的研究](https://research.google/blog/deeper-insights-into-retrieval-augmented-generation-the-role-of-sufficient-context/)

上传文件也不一定就是 RAG：有的应用把全文放入上下文，有的先检索片段，还有的结合使用。作为使用者，先关心它是否拿到了相关资料，以及回答能否回到原文核对。

### Tool（工具）：执行具体操作的能力

模型可以提出“把文章保存成文件”，真正执行保存动作的是文件工具。写作时，搜索工具可以查找参考资料，文件读取工具可以读取已有素材，文件写入工具可以保存初稿。

一次工具调用，可以理解为 AI 向工具发出一个具体请求，再接收执行结果。**AI 说“已完成”，不等于操作一定成功**；生成文件要打开检查，查找资料要查看来源。

不需要一开始就安装很多工具。先确定任务，再选择所需能力，并核对它能读取哪些资料、修改哪些内容。

### Skill（技能）：可复用的做事方法

Tool 提供操作能力，Skill 则把某类任务的做法整理下来，供 Agent 按需使用。例如，你已经跑通了一个公众号写作工作流：明确主题和读者，整理素材，拟提纲，写初稿，核对事实，再保存稿件。“工作流”就是这些步骤及其先后关系。

可以把这套流程、提纲模板和审稿要求整理成一个写作 Skill，让 Agent 遇到同类任务时按这套方法推进，并调用所需工具。Skill 还可以规定：素材不足时先提问，提纲经你确认后再写正文。它复用的是做事方法，每次文章的主题和材料仍需提供。

在 Agent Skills 开放格式中，一个 Skill 通常包含说明文件，也可以附带脚本、模板和参考材料。不同产品对“技能”的具体实现可能不同。[Agent Skills 官方说明](https://agentskills.io/home)

开始学习时先把一个任务做对。等同类任务需要重复完成，再考虑把方法保存为 Skill。

### MCP（模型上下文协议）：连接工具与数据的通用约定

MCP 是 Model Context Protocol 的缩写，是连接 AI 应用与外部系统的开放协议。它约定双方如何交换信息，让支持它的应用更容易接入工具与数据源，可以类比为统一接口。[MCP 官方介绍](https://modelcontextprotocol.io/docs/getting-started/intro)

例如，假设你存放写作素材的文档服务提供了 MCP 服务，支持 MCP 的 AI 应用完成连接和授权后，就可能检索、读取其中的素材。能否把稿件写回去，还要看服务是否开放了写入工具，以及你是否授权。

MCP 本身不提供无限权限，也不是操作软件的唯一方式。应用还可能通过内置工具、API 或界面自动化完成任务。对初学者来说，遇到具体连接需求时再配置即可。

## 4．开始前的准备清单

先准备能完成一个小任务的环境。工具不必一次装齐，下面的选项也不需要全部注册。

### 必备：电脑、可用账号和练习材料

- **一台电脑**：后续会涉及文件和文件夹操作，使用自己熟悉的系统即可。
- **稳定访问所选服务的网络与账号**：先确认能打开官方入口、登录并发送一条消息。使用条件取决于服务支持的地区、账号和设备；更换网络不等于自动满足这些条件。
- **一份不含隐私的练习材料**：可以直接用本章的虚构写作需求和要点。先用小材料练习，结果更容易核对。
- **明确的成果要求**：例如“在对话中得到文章初稿”，或“得到一个能打开的稿件文件”。两者需要的工具能力不同。本章练习只生成初稿，不需要注册公众号或发布文章。

如果遇到登录或访问问题，先查看官方帮助中的账号与地区要求；暂时无法使用的工具可以跳过，不必让它阻塞基础练习。

### 基础格式：认识 Markdown

Markdown 是用简单符号表示标题、列表和强调等结构的文本格式，文件通常以 `.md` 结尾。本教程的正文也使用这种格式。

先认识下面几种写法即可，注意标题和列表符号后面的空格：

```markdown
# 下班后怎样留出一点阅读时间

## 从一个小行动开始

- 每天读 10 分钟
- 读完记下一句话

**先选一个做法尝试。**
```

支持 Markdown 的阅读器会把它显示为标题、列表和加粗文字。普通文本编辑器也能读取内容，只是可能直接显示这些符号。

Markdown 常用于 AI 任务说明和项目文档，但不是所有 AI 文件都必须使用它。先能识别标题和列表即可，不需要为此安装专门的笔记软件。

### 可选：用 Gemini 作为日常问答入口

[Gemini](https://gemini.google.com/) 是 Google 提供的 AI 助手，可作为解释概念、整理内容和练习提示词的入口。是否能使用某项功能，应以当前账号和设备的实际界面为准。[Google 的 Gemini 应用说明](https://blog.google/products-and-platforms/products/gemini/gemini-iphone-app/)

已经有稳定使用的 AI 应用，也可以先用它完成本章练习。选择标准是能顺利使用、能处理自己的材料、结果便于核对，而不是只看品牌或排行榜。

### 可选：用 WorkBuddy 体验 Agent 任务

[WorkBuddy](https://www.workbuddy.cn/) 可作为体验文件处理、文档生成等任务的候选入口。其官方指南提供了从安装、登录、新建任务到查看结果的流程。[WorkBuddy 官方入门指南](https://www.codebuddy.cn/docs/workbuddy/FirstTask)

想体验“从材料到文件”的读者，可以优先了解这类带图形界面的 Agent。开始前查看适配系统、费用与用量限制；本教程不把试用赠送额度或签到活动当作长期免费承诺。

本章只提供选型入口，尚未实测 Gemini、WorkBuddy 的安装、登录与文件任务，也未确定后续章节的演示工具。具体工具的安装与配置指南持续更新中。当前无需先配置命令行工具、MCP 或 Skill。

## 5．用一个小练习检查理解

如果已经能使用一个 AI 对话应用，在新对话的输入框中粘贴第 3 节的完整写作提示词，发送后检查三件事：

1. 是否围绕上班族的阅读问题，覆盖三个要点，并为每个要点给出可执行的建议？
2. 是否编造了作者经历、研究数据或名人名言？举例是否明确为假设场景？
3. 是否包含标题、三个小标题和结尾行动建议，篇幅是否接近要求？

文章可以有不同表达，不必与某一份固定答案逐字相同。判断是否完成任务，先看这些要求有没有满足，再看表达是否合适。如果出现编造经历或建议空泛的情况，可以继续发送：

```text
请对照最初的写作要求修改初稿：
删除没有依据的作者经历、研究数据和名人名言。
将空泛建议改成下班后就能做的具体行动。
保留三个要点；需要举例时，明确写成“比如，你可以……”。
```

这个练习只要求在对话中生成文章初稿。如果回复说“已经保存”，却没有可打开的文件或下载入口，就不能认为完成了文件交付。初稿也不等于可直接发布的定稿，使用前仍要核对内容。
