# 04．给 Agent 立规矩：长期规则文档（AGENTS.md）怎么写

最近有个梗：**“立好规矩不烧心。”** 这话用在 AI 上也非常合适。

前三章我们认识了 Agent、划定了安全边界，也完成了 GitHub 账号注册。但日常高频用的时候，很容易遇到一件“烧心”事：每次新开对话窗口，Agent 都把我们之前交代过的身份、规矩、偏好和工作底线忘得一干二净，导致我们要反复说，很麻烦。

这一章就来解决这个问题——写一份**长期规则文档（`AGENTS.md`）**，让 Agent 每次开工前自动读一遍，长期记住我们是谁、喜欢怎么沟通、要按什么规矩办事。

## 1．没有长期规则文档，用 Agent 常遇到的五个痛点

平时用 Agent 写公众号文章、整理会议纪要或汇总表格时，如果只靠对话框里临时口头交代，很容易遇到这五种抓狂情况：

- **没记性**：上次花五分钟交代完“我是做市场运营的，用中文口语化回答，别写‘赋能、抓手、闭环’”，今天新开一个窗口，它又开始“大词”输出。
- **爱讨好**：不管我们的想法有没有漏洞，它一上来总是“好的”“这是个绝妙的主意”，顺着错误方向一路做下去，直到结果完全没法用。
- **容易灵机一动**：只让它润色一段文案，它顺手把全文结构改了，还塞上我并不想要的表情符号；让它改一列数据，它顺手把表头也换了。
- **爱逞强**：碰到不确定的事实或报错，它不直说“我不确定”，而是自信地猜一个答案让我们去试；试错了再换一个猜，带着我们原地打转。
- **同一个坑反复踩**：上个对话刚纠正过的错误（如把草稿当成终稿、把书名和作者张冠李戴），新开一个窗口照犯不误。

为什么会这样？可以把 Agent 理解成我们刚招来的一位**985 硕士新助理**：学历高、领悟快、干活麻利，但有个天然局限——每次新开对话，对他来说都像“刚入职的第一天”，既不了解我们的职业背景，也不知道哪些事不能自作主张。

想让这位得力助理稳定地按我们的习惯干活，最管用的办法就是**写一份《入职工作手册》放在他的工位上，规定每次开工前必须先读一遍**。这份写给 Agent 的《工作手册》，就是本章要讲的**长期规则文档**。

## 2．长期规则文档：通用规则与项目规则

**长期规则文档是一份存放在电脑固定位置的纯文本文件（通常为 Markdown 格式，如 `AGENTS.md`）。Agent 每次启动新对话时会自动读取它，把里面的内容作为本次工作的前提规矩。**

在 AI 行业和不同工具里，它的官方叫法略有不同，其实指的都是同一件事：
- **Rules（规则文件）**：Cursor、Google Antigravity、Grok CLI 采用的叫法；
- **Memory（记忆文件）**：Claude Code、Qwen Code 采用的叫法；
- **Instructions（指令文件）**：OpenAI Codex 与 `AGENTS.md` 开放标准采用的叫法；
- **全局配置**：技术社区对“跨项目通用规则文件”的习惯统称。

日常协作中，向 Agent 交代要求的三种方式分工如下：

| 交代方式 | 生效范围 | 适合放什么 | 局限 |
|---|---|---|---|
| **对话框口头交代** | 仅当前对话窗口 | 本次任务的具体目标、临时要求 | 关掉窗口就忘，下次得重说 |
| **长期规则文档（本章重点）** | 每次新对话自动加载 | 长期稳定的个人背景、偏好、工作纪律与安全红线 | 需要我们主动编写和更新 |
| **工具自带的自动记忆** | 工具后台自动提取 | 零散的历史偏好或项目事实 | 黑盒机制，记了什么不完全受我们控制 |

简单说：**口头交代管“这一次”，规则文档管“每一次”。**

在实际使用中，长期规则文档分为上下两层，叠加生效：

- **通用规则（全局级 / Global Rules）**：放在电脑的个人主目录下，**对这台电脑上的所有项目、所有新对话都生效**。适合写“我是谁、沟通风格、通用办公习惯、安全红线”。
- **项目规则（项目级 / Project Rules）**：放在某个具体的工作文件夹里，**只对当前这个文件夹里的任务生效**。适合写“这个项目是做什么的、文件怎么归档、有哪些特殊要求”。

两层同时存在时，遵循**“就近原则”**：**对话框当次指令 ＞ 项目规则 ＞ 通用规则（全局级）**。

## 3．为什么要写规则文档，以及它的能力边界

花十分钟写好一份规则文档，能带来三个直接好处：

1. **一次编写，永久省心**：身份、禁忌词、输出标准写一次，以后开新窗口直接说任务，不用再铺垫背景。
2. **把翻车教训变成“错题本”**：Agent 犯过的错，光在当前对话里批评没用。写成一条具体禁令放进规则文档，它每次开工都会看到，同一个坑不再踩第二次。
3. **跨工具无缝迁移**：写下来的纯文本规矩完全归我们自己所有，换用任何新 Agent 工具，把文件复制过去就能立刻接上。

同时也要清楚它的边界：**规则文档是“工作规范”，不是“物理锁”。**

当任务极复杂或对话很长时，Agent 偶尔仍可能看漏文档里的某句话。因此，回想[第二章安全常识](02.使用-Agent-前，先知道这些安全常识.md)：涉及**删除重要文件、动用账号密码、付款交易、正式对外发布**等高风险动作，除了在规则文档里写明“必须先问我”，还要配合工具本身的**权限审批机制（需点击确认才能执行）**。文档负责“立规矩让它别乱动”，权限负责“守底线让它动不了”。

**看懂表格里的路径符号：**
- `~` 代表电脑上的**个人账户主目录（家目录）**：Mac 上是 `/Users/你的用户名/`，Windows 上是 `C:\Users\你的用户名\`。
- 点号 `.` 开头的文件夹（如 `.claude`、`.codex`）默认隐藏：Mac 访达按 `Command + Shift + .`、Windows 资源管理器勾选“查看 → 显示 → 隐藏的项目”即可看到；更省事的做法是直接让 Agent 帮我们创建。
- **跨工具共同趋势**：由开源社区与 Linux 基金会维护的 **`AGENTS.md` 已成为通用标准**，表中 8 款工具全部直接支持或兼容读取。

### 4.2 多工具共用一份文档的最佳实践

现在 Agent 工具很多，我们经常会用到多个工具，每个工具都配置一遍很麻烦，也很容易改了一处忘了另一处。**“只维护一份正本，所有工具同步生效”**的最佳做法分两步：

1. **项目规则：统一以项目根目录的 `AGENTS.md` 为唯一母本**
   - Codex、Kimi Code、ZCode、Qwen Code、Grok、Antigravity、Cursor 打开项目时都会直接读 `AGENTS.md`。
   - 如果同时用 **Claude Code**，只需在同目录建一个 `CLAUDE.md`，里面只写一行 `@AGENTS.md`（Claude Code 支持用 `@文件名` 自动导入全文，本教程仓库正是这样配置的）。
2. **通用规则（全局级）：主文件 + 软链接/引用**
   - 把通用规则统一写在 `~/.codex/AGENTS.md` 作为唯一母本，然后发下面这段话给你的 Agent，让它帮你把其他工具的全局路径绑定过来，以后只改一处即可：
   ```text
   请帮我把 ~/.codex/AGENTS.md 作为我的全局规则唯一母本。
   请先检查 ~/.claude/CLAUDE.md、~/.kimi-code/AGENTS.md、~/.gemini/GEMINI.md 是否存在（若存在先备份），
   再帮我通过系统软链接（或 @ 引用）将它们指向 ~/.codex/AGENTS.md，确保我只改母本就能在所有工具生效。
   ```
   *(注：Cursor 的全局 `User Rules` 存在软件界面内，把极少改动的几行个人偏好粘贴进去即可，经常调整的规则尽量放项目级 `AGENTS.md`。)*

### 4.3 文档大小与长度控制的最佳实践

规则文档每次对话都会占用第一章讲过的“上下文窗口（工作台）”。**文档绝不是越长越好**：塞进几千字不仅消耗 Token，还会触发**“指令稀释”**（模型注意力分散，漏看夹在中间的红线），甚至超出工具上限（如 Antigravity 的 24 KB、Claude Code 建议的 200 行）被直接截断。

四条大小控制最佳实践：
1. **守住黄金篇幅线**：通用规则（全局级）控制在 **80～150 行（约 1,000～2,000 字）以内**；项目规则控制在 **150～200 行（约 2,500 字）以内**。
2. **“高频热规则”与“低频冷资料”分离**：80% 以上对话都要守的规矩放规则文档；只有特定任务才用的长篇材料（如《公众号排版细则》《术语词典》）单独存成普通文件，在规则文档里只留一行**路径索引**：
   > `- 撰写或排版公众号文章前，请先读取 docs/公众号排版规范.md 并按其标准执行。`
3. **去掉客套铺垫，一条一句**：用“动词 + 可检验标准”写短句列表（例如写“成稿 2,000 字以内”，不写“请你尽量把篇幅控制得精炼一些”）。
4. **定期合并瘦身**：同类翻车教训攒到四五条时，提炼合并成一条通用规则，删掉过时的临时叮嘱。

## 5．规则文档怎么写：分层原则与办公白领最佳实践模板

### 5.1 内容分层原则：放全局、放项目还是拆出去

| 类别 | 存放位置 | 典型内容 |
|---|---|---|
| **跨所有任务通用的个人规矩** | **通用规则（全局级）** | 我是谁与暗号称呼、沟通文风、任务推进流程、内容纪律、安全红线与错题本 |
| **只在当前工作文件夹生效的规矩** | **项目规则（项目级）** | 项目目标与受众、目录约定、该项目专属流程、该项目踩过的坑 |
| **长篇参考资料、范文与操作细则** | **拆出为独立文件** | 历史爆款范文、长篇排版手册、业务背景资料（在规则文档中只留一行路径索引） |

### 5.2 通用规则（全局级）：办公白领最佳实践模板

下面这份通用规则模板专为**办公白领与内容创作者**（公众号/新媒体写作、汇报与周报起草、会议纪要整理、表格数据汇总、日常办公提效）打磨。全文严格按 4.3 节的最佳实践编写，去掉所有客套铺垫，采用“动词 + 可检验标准”的短句列表，共 **6 个模块、36 行、约 760 字**（远低于 80～150 行的上限）。使用时只需把 `【 】` 里的内容换成我们自己的实际情况：

```markdown
# 个人通用规则（AGENTS.md）

## 1. 关于我与在线暗号
- 我是【姓名/昵称】，在【行业/公司类型，如：消费品公司】做【岗位，如：品牌与内容运营】。
- 常办任务：【如：公众号长文写作、周报与方案汇报起草、会议纪要整理、表格数据汇总】。
- 无编程背景：涉及命令行、代码或系统配置时，先用大白话说明作用，再给操作步骤。
- 固定称呼：每次回复开头必须先称呼我「【专属称呼，如：主人】」。

## 2. 沟通与文风
- 默认使用简体中文；专业术语、文件名或命令保留原样并附一句中文解释。
- 结论先行：直接给结论或修改结果，再简述理由，禁止寒暄铺垫与夸奖客套（如“很好的问题”“绝妙的想法”）。
- 直指问题：发现我的想法、选题或方案有逻辑漏洞，直接指出并给替代方案，禁止顺从迎合。
- 平实文风：禁用“赋能、抓手、闭环、底层逻辑、组合拳”等空洞黑话，不用感叹号和 Emoji，少用“首先、其次、最后”机械排比。

## 3. 任务推进流程
- 先读项目规则：进入工作文件夹先检查是否存在项目级 `AGENTS.md`，按其目录与命名约定执行。
- 模糊处先给方案：小细节不明确时，按最合理假设先出一版可用结果，末尾附 1～2 个待确认点，不要连环追问。
- 大动作先对齐：写长文、起草重要汇报或批量处理超过 3 个文件前，先给【大纲 / 处理方案 / 修改范围】，经我确认再动手。

## 4. 内容与资料纪律
- 严禁编造：数据、案例、引语、书名必须核对来源；缺失信息统一留出 `【待补充：具体内容】` 占位符，禁止估算或虚构。
- 精准修改：润色或修改指定段落、数据时，只改指定范围，禁止顺手改写其他段落或删减原有信息。
- 事实与建议分离：整理会议纪要或长文档时，先忠实还原原文要点，再单独列出补充建议。
- 排查不瞎猜：遇到报错或不确定的功能先查一手官方文档；连续两次尝试未解决立即停下汇总现状，禁止让我反复盲试。

## 5. 安全红线（必须先问我）
执行以下操作前，必须先说明影响并获我明确同意：
- 删除、移动或覆盖现有重要文件、原始素材与历史归档。
- 公开发布文章、发送外部邮件/消息、上传文件或提交远程代码仓库。
- 接触账号密码、密钥（Token/SSH）、付款交易或个人隐私资料。
- 修改系统设置、安装新软件或全局工具。

## 6. 错题本（禁止重犯）
- 【示例，日常使用中替换】2026-11-01：润色初稿时擅自删掉文末读者留言。教训：原始素材与真实案例未经允许一律不得删改。
- 【示例，日常使用中替换】2026-11-03：整理月度数据表时用前两月均值填补缺失数据。教训：缺失数据必须留空并标明“待核实”。
```

**模板设计说明：**

- **模块 2～6 一一对应第 1 节的痛点**：第 2 节治“爱讨好与大词黑话”，第 3 节治“不看规矩直接抢跑”，第 4 节治“编造数据、容易灵机一动乱改原文与遇到问题爱逞强”，第 5 节守住安全底线，第 6 节则是防“同一个坑反复踩”的错题本。
- **为什么第 1 节要规定每次回复开头叫一个“固定称呼”？**
  这不是为了仪式感，而是用它当**规则有没有掉线的实时报警器**：
  1. **新开对话时**：看它第一句有没有叫这个称呼，一秒就能确认规则文档路径放对了、已成功加载。
  2. **长对话进行中（更关键）**：当对话聊了几十轮或读了多个大文件后，上下文窗口会被塞满并触发自动压缩，AI 很可能把开头的规则文档“挤出去”忘掉。**一旦某轮回复它突然不叫你的专属称呼了，就说明它此时很可能已经丢掉了规则文档（包括里面的安全红线）**，这时立刻新开一个窗口或让它重读一次规则文件即可。

### 5.3 项目规则模板与公众号写作示例

有了上面的通用规则打底，每个工作文件夹里的**项目规则（`AGENTS.md`）**只需短短十几行，写明“这个项目独特的地方”即可。以下为虚构人物小林的公众号项目 `AGENTS.md` 示例（共 20 行、约 310 字，可直接套用结构）：

```markdown
# 项目规则：公众号「下班后读点书」

## 1. 项目背景与读者
- 存放公众号「下班后读点书」的选题、读书笔记素材与稿件。读者是想读书但下班总刷手机的上班族，重在提供“今晚就能试”的具体小办法。

## 2. 目录与文件约定
- `notes/`：平时记的原文摘抄和个人感想，起草时从中提取素材，只读不改。
- `drafts/`：正在写的草稿，统一命名为 `YYYY-MM-DD-标题.md`。
- `published/`：已发布终稿，仅作参考，禁止修改。

## 3. 本项目特殊要求
- 每篇写前先给 3 个备选标题和 1 份大纲，我选定后再写正文。
- 成稿控制在 1,500～2,200 字，小标题不超过 4 个，结尾留一个读者互动问题。

## 4. 关联详细规范（按需读取）
- 需要生成封面图提示词或做排版检查时，先阅读 `guides/排版与配图清单.md`。

## 5. 本项目易错提醒
- 文中提到的书名、作者和原书金句，必须与 `notes/` 里的摘抄逐字核对，拿不准立刻问我。
```

## 6．实操方法：三步创建、验证与日常更新

不用自己从头手敲，也不需要手动找隐藏文件夹，按下面三步就能直接让 Agent 帮我们把全局规则配好并跑通：

### 第一步：发提示词，让 Agent 定制并写入规则文件

打开你正在用的 Agent 工具，把 **5.2 节的模板**连同下面这段提示词一起发给它（若使用 Cursor，将它生成的文本直接粘贴到软件 `Cursor Settings → Rules → User Rules` 即可）：

```text
请帮我配置我的全局规则文档。
我当前使用的工具是：【填入工具名，如：Claude Code / Codex CLI / Antigravity / Kimi Code / Qwen Code】。
我的电脑系统是：【Mac / Windows】。

请按以下步骤执行：
1. 根据上面提供的「个人通用规则模板」和下面我的个人情况，生成一份定制好的 Markdown 内容（保留模板核心纪律，结合我的职业微调第 1、4 节）。
2. 先把生成好的内容发给我审阅，不要直接写入文件。
3. 等我回复“确认写入”后，先检查我电脑上该工具对应的全局规则文件是否已存在（若存在请先备份），再写入对应路径，并告诉我文件保存在哪里。

我的个人情况：
- 每次回复开头对我的专属称呼：【如：小林】
- 我的行业与岗位：【如：教育行业课程策划】
- 我最常用你做的 3 件事：【如：写公众号推文、整理课程大纲、汇总学员反馈表】
- 我最讨厌的 AI 毛病：【如：讨厌端着架子说教、讨厌乱用感叹号和废话铺垫】
- 我以前踩过的坑（放入第 6 节）：【如：有一次让它改错别字，它把我原本写好的案例全删光了】
```

### 第二步：新开窗口，验收规则是否生效

文件写入成功后，**关闭当前对话，新开一个全新对话窗口**，发送：

```text
你好，我是做什么工作的？我们之间有哪些安全红线？
```

- **预期结果**：回复开头先叫出你的**专属称呼**，并准确答出你的岗位与第 5 节安全红线。
- **未生效排查**：若没叫专属称呼或答不上来，依次检查：① 是否已重新开启新窗口；② 对照 **4.1 节表格**检查文件路径与文件名大小写（如 `AGENTS.md` 别变成 `AGENTS.md.txt`，可用 `/memory`、`grok inspect` 等工具命令查看加载状态）。

### 第三步：日常用“一句话记账法”持续更新

以后在日常使用中，每当 Agent 犯了一个典型错误，当场纠正它之后，顺手补发一句话即可完成规则升级：

```text
请把刚才这次错误的原因和教训缩成一句话，加上今天日期，追加到我的全局规则文档第 6 节「错题本」里。
```

### 本章实操重点总结

- **先配全局、再补项目**：先把跨任务通用的个人规则配好；常驻的固定工作文件夹，再按 5.3 节补一份十几行的项目级 `AGENTS.md`。
- **保持精炼、长资料外挂**：规则文档只放高频硬规矩（控制在百行、千字左右），长篇排版手册或参考范文拆成独立文件，只留一行路径索引。
- **改完开新窗、平时看称呼**：修改规则后新开对话窗口生效；日常对话中留意开头的“专属称呼”是否还在，一旦消失就及时重开窗口或重读规则。
